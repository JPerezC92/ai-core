## Specs

- S1 — The shared skills live under `.agents/skills/`, which every supported editor discovers natively, and no skill is duplicated into an editor-specific directory. Exact requirement: "U2: Canonical shared skills under `.agents/skills/`." and "`.agents/skills/` is canonical for both OpenCode and Cursor." Acceptance: the clearance registry names `.agents/skills/<name>/` for every shared skill, the source holds exactly one copy of each skill, and a newly enrolled destination receives each skill at `.agents/skills/<name>/`.
- S2 — The shared documentation is consolidated under `.aicore/core/` in the source and in the destination, while destination-owned synchronization state stays where it is. Exact requirement: "U3: Consolidation under `.aicore/core/` in both source and destination." Acceptance: the source holds `architecture/`, `knowledge/` and `odd/` under `.aicore/core/`, every live reference to a moved path is updated in the same change, and no compatibility layer is introduced.
- S3 — The synchronization engine is TypeScript, with no Python engine and no `uv` dependency retained. Exact requirement: "U5: One TypeScript synchronization engine replacing Python." and "The final synchronization engine must be TypeScript, without Python or `uv` dependencies." Acceptance: the TypeScript engine passes an independently authored parity corpus, the Python engine and its engine-specific tests are removed, and no code path spawns `uv` or a Python interpreter for synchronization. **Blocker carried by this requirement:** the corpus's three symlink safety cases are skipped on a host without symlink privilege, so parity cannot be claimed until those three cases are independently verified where symlink creation is permitted. **The Python engine has since been removed from the repository** — the removal is recorded in the Log — together with its own test suite and the parity corpus's reference binding, and the consequence is recorded rather than softened: the corpus can no longer replay its cases against the reference engine, so from the removal onward it judges the TypeScript engine alone.
- S4 — OpenCode and Cursor are both supported distribution targets, with editor-specific agent delivery, a shared content contract, and an explicit statement of what is not enforced for an editor without a project-level permission channel. Exact requirement: "U4: OpenCode and Cursor support, with honest treatment of permission differences." and "Cursor support must disclose limitations in project configuration and enforceable Git permissions. Do not claim unsupported security guarantees." Acceptance: both editors are accepted by the CLI, each receives the content the same way, agents are delivered to each editor's own agent directory, and the delivered documentation states that project configuration and Git permission enforcement are not delivered to an editor without a project-level permission channel.
- S5 — The utilities distributed to destinations are TypeScript, keep TypeScript as the authoritative source, execute standalone without a destination-side installation, and impose no unnecessary runtime version. Exact requirement: "U6: Migration of distributed Python functionality needed by destinations." Acceptance: no Python file remains in a distributed path, each distributed utility runs in a destination without an install step, and its documented runtime prerequisite is stated and checked at run time.
- S6 — Destination reconciliation is proposed and inspectable before any destination file is changed, identifies AICore-managed, superseded, locally modified and destination-owned files, and never deletes a file whose ownership or modifications cannot be established. Exact requirement: "Prefer a safe, inspectable reconciliation process over manual mass editing." Acceptance: the proposal lists managed, superseded, modified, untracked and destination-owned files with the proposed moves and deletions, writes nothing to the destination, and preserves and reports any file whose ownership it cannot establish.
- S7 — The durable capability file states the migration's guarantees, and each unit ticks only what it has verified. Exact requirement: "Keep ADR 0009 and the Vitest change record consistent with their actual acceptance and closure states." Acceptance: the durable feature file's derived status follows its ticks, and every requirement it carries is evidenced by this record.
