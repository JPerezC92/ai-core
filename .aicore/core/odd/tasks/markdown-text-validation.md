## Specs

- S1 — Establish one explicit Markdown text-integrity policy in `knowledge/unicode-policy.json`; update `knowledge/unicode-policy.md` to explain it rather than maintain another character table. Preserve existing permission for typographic prose punctuation and verbatim quotations. Normal Unicode, accents, non-Latin languages, role emoji, variation selectors and emoji joiner sequences are not errors merely because they are non-ASCII. No ASCII-only mode, mass normalization or automatic Markdown edits.
- S2 — Machine policy uses a versioned, validated schema with stable rule IDs, Unicode scalar values/ranges, severity and rationale; unknown or malformed policy fails explicitly. Classify invalid UTF-8, NUL and unexpected C0/C1 controls as errors, allowing ordinary tab/newline/carriage return. Report bidi-formatting controls, zero-width space, non-breaking space, soft hyphen and replacement-character occurrences as contextual warnings, not universal source defects. Do not infer a malicious or broken file from a highlight. Do not flag ZWJ, ZWNJ or variation selectors by themselves: legitimate script/emoji contexts must remain supported. Explain residual detection limits, including encoding corruption that is valid Unicode.
- S3 — Provide a read-only general checker for explicit Markdown file/directory inputs, not just skills. Require an explicit `--policy PATH`; use deterministic traversal/output, include dot-directories, do not follow symlinks or silently scan secrets/output/virtual environments. Report file, one-based line and Unicode-codepoint column, rule ID, severity, `U+XXXX`/Unicode name where applicable; escape diagnostic excerpts and never emit raw controls. Exit 0 for no errors (warnings may exist), 1 for content errors, 2 for policy/input/IO failures. Missing files and invalid policies never produce a clean result. No repository mutation, formatting, Git, network or runtime dependency installation.
- S4 — Keep Markdown text integrity separate from skill metadata, feature anatomy and fenced-language validation. En dashes in descriptive numeric ranges, including inline code, remain permitted; do not guess executable syntax from backticks or use a naive fence parser. Document intentional-control examples using escaped spellings; any actual-character exception mechanism must be narrow, reasoned and validated, not a blanket file exclusion. No suppression interface is required for contextual warnings because warnings do not fail validation.
- S5 — Align `.vscode/settings.json` with the canonical policy using a checked projection, without copying Gremlins defaults into a second policy. Check only the representable Markdown character overrides; preserve unrelated settings and non-Markdown behavior. State explicitly that editor codepoint highlighting cannot provide the checker's complete semantics and that a live editor reload/verification is distinct from static validation. Do not claim runtime editor behavior without observing it.
- S6 — Implement stdlib-only feature-scoped Python tooling under `.opencode/skills/op-skill-creator/scripts/`: thin CLI, pure domain rules, one application `execute()` with injected policy/file ports, infrastructure IO and edge serialization. Follow the current common/scripts/Python and testing contracts. The checker accepts any supplied Markdown path; package placement does not restrict it to skill files. Project policy/invocations are project-owned; shared skill references do not hardcode a source-only policy path or imply destination synchronization. No new distribution-clearance rows, CI gate or mandatory every-task check in this scope.
- S7 — Test permitted punctuation, prose ranges in/out of backticks, accented and non-Latin text, single/compound emoji, valid joiner/script text, escaped examples, actual warning controls, NUL/control/invalid UTF-8 errors, malformed policy, missing/unreadable inputs, deterministic discovery including dot-directories, symlink/exclusion boundaries, positions, escaped diagnostics, exit codes and editor-projection drift. Test domain/application/IO/CLI boundaries without fabricated shared payloads or unnecessary wrappers. Record exact inputs, expected/observed results, executors, commands and exit status in this Log. Real-repository scans report findings without fixing Markdown automatically.

Capture fresh branch/worktree/PR state through Herald 📯 (Release Manager) before implementation; preserve existing work and isolate this feature as needed.
