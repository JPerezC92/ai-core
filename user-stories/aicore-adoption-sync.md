> **Created:** 2026-09-11

## Persona

- A maintainer on either side of the core/destination boundary: the destination maintainer who must receive every core update without losing project-owned behavior, and the AICore maintainer who ships the core by a deterministic copy-paste only.

## Goal

- **G:** AICore source files define core bytes: markerless files use the post-frontmatter body; marked files use only their `core` region. A destination region file = `frontmatter` + core region (byte-identical) + a blank line + a destination-owned `project` region. `core-sync` is the only writer of source-derived core bytes, raw whole-file copies, and the reconciliation blocker; the destination alone edits its `project` region.
  - Done when: `init` generates a markerless region destination into core + project regions and sets `pending`, while raw destinations copy whole source bytes without regions; `init --bind-raw` can create an absent target for a newly declared raw mapping when its parent exists, but a missing target for an existing raw binding remains drift; `apply` refreshes region cores and raw files; `check` exits 0 only when every region core matches, every raw file byte-matches, and region `pending` is empty; drift/missing/stale-pending states exit 1 and malformed bindings or invalid region-destination markers exit 2; the tool writes and clears the destination-root blocker for region paths.

## Scenario

- The core maintainer runs `core-sync init` from the AICore checkout against a clean, saved destination. Region bindings generate core/project regions, set `pending`, and write reconciliation reports; raw bindings copy whole source files byte-for-byte without markers or `pending`. A newly declared raw mapping may create an absent target when its parent directory exists; an absent target for an existing raw mapping remains drift. The script writes the destination-root blocker for region paths. The destination project then reconciles its `project` regions, clears `pending`, and the next `check` reports `current`. Routine core updates run `apply` then `check`. The tool never edits the `project` region, and the core never hand-copies synchronized destination files.
