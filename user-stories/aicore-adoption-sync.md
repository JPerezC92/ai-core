# User story — aicore-adoption-sync

> **Created:** 2026-09-11
> **Title:** Core region synchronization
> **Status:** active
> **version:** 1.0.0
> **Epic:** core-governance
> **Affected areas:** `.opencode/agents/`, `.opencode/skills/core-sync/`, `agents/`, `README.md`, `AGENTS.md`, `knowledge/agents.md`, `opencode.jsonc`

## Persona

- A maintainer on either side of the core/destination boundary: the destination maintainer who must receive every core update without losing project-owned behavior, and the AICore maintainer who ships the core by a deterministic copy-paste only.

## Goal

- **G:** AICore source files define core bytes: markerless files use the post-frontmatter body; marked files use only their `core` region. A destination region file = `frontmatter` + core region (byte-identical) + a blank line + a destination-owned `project` region. `core-sync` is the only writer of source-derived core bytes, raw whole-file copies, and the reconciliation blocker; the destination alone edits its `project` region.
  - Done when: `init` generates a markerless region destination into core + project regions and sets `pending`, while raw destinations copy whole source bytes without regions; `apply` refreshes region cores and raw files; `check` exits 0 only when every region core matches, every raw file byte-matches, and region `pending` is empty; drift/missing/stale-pending states exit 1 and malformed bindings or invalid region-destination markers exit 2; the tool writes and clears the destination-root blocker for region paths.

## Scenario

- The core maintainer runs `core-sync init` from the AICore checkout against a clean, saved destination. Region bindings generate core/project regions, set `pending`, and write reconciliation reports; raw bindings copy whole source files byte-for-byte without markers or `pending`. The script writes the destination-root blocker for region paths. The destination project then reconciles its `project` regions, clears `pending`, and the next `check` reports `current`. Routine core updates run `apply` then `check`. The tool never edits the `project` region, and the core never hand-copies synchronized destination files.

## Acceptance criteria

- ✅ Region markers are project-agnostic: `<!-- core:begin -->` / `<!-- core:end -->` and `<!-- project:begin -->` / `<!-- project:end -->` (no project name; the tool's constants use exactly these). Evidence: `test_core_sync_markers.py::MarkerValidationTests`, `test_core_sync_regions.py::RegionDecompositionTests`; verification: `uv run --frozen --group dev pytest -q` → exit 0.
- ✅ `core-sync init` generates a markerless destination deterministically (frontmatter + core region = the AICore body + a blank line + project region = the destination's existing body), refreshes marked region files while preserving bytes outside the core region, sets `pending`, and writes a reconciliation report. Evidence: `test_core_sync_init.py::InitContractTests`, `test_core_sync_init_refresh.py::InitRefreshTests`; verification: `uv run --frozen --group dev pytest -q` → exit 0.
- ✅ `core-sync apply` refreshes only the core region and proves the outside-marker bytes are unchanged; `check` exits 0 only when every region core byte-matches, every raw destination byte-matches, and region `pending` is empty; drift/missing/stale-pending exits 1 and malformed bindings or invalid region-destination markers exit 2. Evidence: `test_core_sync_apply.py::ApplyContractTests`, `test_core_sync_check.py::CheckContractTests`, `test_core_sync_check_raw_mode.py::RawCheckTests`; verification: `uv run --frozen --group dev pytest -q` → exit 0.
- ✅ The tool writes a self-contained, step-by-step reconciliation blocker into the destination root when region paths are pending and removes it when those paths are reconciled; the blocker tells the destination to permanently adopt the core-region rule, reconcile, clear `pending`, and delete the blocker. Evidence: `ReconcileBlockerContentTests`, `ReconcileBlockerLifecycleTests`, `BlockerFenceHandlingTests`, `CheckBlockerWiringTests`, `ApplyBlockerWiringTests`, `InitBlockerWiringTests`, and `RootSelectionTests`; verification: `uv run --frozen --group dev pytest -q` → exit 0.
- ✅ Bindings support per-entry `region` (default) and `raw` modes: `init`/`apply` copy raw source bytes exactly, `check` exits 0 for equal bytes, and raw paths do not create project regions, reports, or `pending`; region and raw entries coexist. Missing/raw-byte drift exits 1; malformed mode or a root/raw target alias exits 2. `apply`/`init` clear stale raw paths from `pending` after a mode change, while `check` rejects stale state and excludes it from the reconciliation blocker. Evidence: `.opencode/skills/core-sync/scripts/core_sync.py`; `BindingModeValidationTests`, `BindingModeSerializationTests`, `BindingModeCoexistenceTests`, `RawPendingNormalizationTests`, `RawCheckTests`, `StaleRawPendingCheckTests`, `RawApplyTests`, `RawInitTests`, `RootRawAliasTests`; verification: `uv run --frozen --group dev pytest -q` → exit 0.
- ✅ `core-sync init` registers region/raw bindings from explicit CLI declarations (`--bind SOURCE=DEST` / `--bind-raw SOURCE=DEST`) and writes the binding metadata itself, so enrollment needs no hand edit to destination `.aicore/core.yaml`. Identical declarations are idempotent; conflicting source/mode mappings or noncanonical path aliases fail before writes. Destination file-content differences do not block synchronization: region `init` preserves them in the project region and blocker, while explicit raw binding overwrites the whole target. Evidence: `InitBindingRegistrationTests`, `InitBindingConflictTests`, `InitBindingValidationTests`; verification `uv run --frozen --group dev pytest -q` → exit 0.
- ✅ Region sources with no exact core marker lines use their whole post-frontmatter body; a valid marker pair uses only its core region; any malformed source marker set fails closed with exit 2 in `check`/`apply`/`init` rather than copying source project content. Evidence: `SourceCoreTests`, `test_core_sync_source_marker_validation.py`; verification: `uv run --frozen --group dev pytest -q` → exit 0.
- ✅ `check`, `apply`, and `init` preflight resolved roots and every write target; overlapping roots, source-contained targets, destination escapes, and blocker/root aliases to raw files fail before mutation. Evidence: `.opencode/skills/core-sync/scripts/core_sync.py`; `RootOverlapTests`, `SourceWriteProtectionTests`, `DestinationWriteBoundariesTests`, `RootRawAliasTests`; verification: `uv run --frozen --group dev pytest -q` → exit 0.
