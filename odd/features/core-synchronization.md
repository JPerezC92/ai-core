# Core synchronization

Synchronization keeps an adopting project's AICore-owned resources current from a pinned source revision: it initializes a destination that is not yet enrolled, updates one that is, preserves what the destination itself owns, and reports what still requires destination-owner reconciliation.

**Status:** achieved

## Requirements

- [x] R1 — A single command synchronizes a destination: it initializes one that is not yet enrolled, updates one that is enrolled, and reports the resulting currency state.
- [x] R2 — The destination and distribution target chosen on a first run are persisted locally and reused by later runs that supply no arguments.
- [x] R3 — An explicitly supplied destination or distribution target overrides the persisted selection, and the persisted selection records the explicit choice.
- [x] R4 — Only a distribution target whose behavior is implemented is accepted; an unimplemented or unknown target is refused with a clear message rather than silently substituted.
- [x] R5 — A distribution target is never inferred for an existing destination whose selection is unknown; the run stops and asks for it explicitly.
- [x] R6 — Source identity is supplied by configuration and never obtained by synchronization executing Git; an absent or malformed identity stops the run rather than falling back implicitly.
- [x] R7 — The destination's synchronization state location and the source checkout location are resolved without per-run arguments.
- [x] R8 — Distribution clearance is enforced: only resources cleared for distribution are delivered to a destination.
- [x] R9 — An updating run that finds a destination not current reports it as not current and refuses to report it as synchronized; a complete per-path account of every difference is a separate inspection operation, not a property of that run.
- [x] R10 — Synchronization never modifies its source resources and keeps operator-local configuration separate from distributed content and destination-owned synchronization records.
- [x] R11 — Unsafe filesystem write targets are refused before any write: a managed path that is a symbolic link, a non-regular file, a path resolving inside the source tree or outside the destination root, and two managed targets that alias one file or one inode.
- [x] R12 — A refusal is distinguished from an applied change: a refused operation writes nothing, an applied operation reports what it changed and what still requires destination-owner reconciliation, and any outcome that leaves a destination not current exits non-zero rather than reporting success.
- [x] R13 — The shared skills live under `.agents/skills/`, which every supported distribution target discovers natively, and no skill is duplicated into a target-specific directory.
- [x] R14 — The shared documentation is consolidated under `.aicore/core/` in the source and in the destination, while destination-owned synchronization state stays separate from it.
- [x] R15 — Editor delivery: each supported editor receives the same shared content at the same paths, agents are delivered to that editor's own agent directory, and every capability the editor cannot receive is documented rather than implied. Agent discovery, shared-skill discovery and instruction loading are each supported by the editor's own documented discovery rules; behavioural equivalence of delegation and enforcement is not claimed.
- [x] R16 — The synchronization engine is TypeScript, and no Python engine or interpreter dependency remains in the synchronization path.
- [x] R17 — A destination owner can inspect a read-only classification of every bound path and every file those bindings' destination directories hold, before any destination file is changed by that inspection: a path whose ownership cannot be established is preserved and reported rather than proposed for deletion. That inspection is not a preview of an updating run's writes; an updating run does not preview its own writes. An inspection never deletes a destination file, and a path whose ownership cannot be established is never deleted by the run that preserves it.
- [x] R18 — Distribution artifacts are ordinary files and directories: a symbolic link or junction in the source is never followed or delivered, a managed destination path that is a link is refused before writing, and existing destination content that synchronization does not manage — including a link — is left untouched. Content synchronization does not manage is never deleted.
- [x] R19 — A distributed payload is independent of the source checkout's dependency installation: dependency installation directories, the version-control directory and interpreter caches never join a distribution set, and an installed and a dependency-free source deliver the same files.
- [x] R20 — The instruction file synchronization writes and hosts its reconciliation notice in is `AGENTS.md`, which both supported editors discover, and an explicitly named instruction file is honoured instead.
- [x] R21 — OpenCode configuration is owned once and lives under `.opencode/` in both the source and an OpenCode destination, with no second configuration file at the project root. Within that single file, settings the core does not define — including provider configuration, a destination's default model, and additional MCP servers by name — survive every later synchronization unmodified, and per-agent model selection is owned by the destination through agent frontmatter. Core-owned permission settings are restored on the next synchronization when a destination has replaced them; that is the synchronization contract, not a runtime security guarantee, and OpenCode's command restrictions have known limitations that this requirement does not close. Survival is demonstrated by a repeated synchronization, not by a single write.
- [x] R22 — A secret-file reference in the relocated configuration resolves inside the destination project's own local secret directory and never outside the project; missing secret files fail predictably rather than by reading some other location; secret contents are never distributed or overwritten. On OpenCode enrollment the destination's secret directory is created when required and missing, existing secret files keep their exact contents, a missing required credential file is created empty, and the destination's Git ignore file gains an effective ignore rule for that directory without duplicating one or rewriting unrelated rules. Synchronization never changes the Git index.
- [x] R23 — A destination can exclude an optional capability, with these distinct behaviors: before enrollment the resource is neither installed nor bound and needs no reconciliation; after installation the exclusion is never reported as effective while the resource remains present, and resolution is reported through the existing reconciliation mechanism with no deletion performed by synchronization; re-enablement by removing the exclusion delivers the resource again on the next synchronization without restoring an exclusion the owner removed; and the mandatory baseline and safety resources cannot be excluded.
- [x] R24 — Distributed configuration references only integrations usable at the destination: portable integrations ship enabled, integrations requiring destination-side setup are identified as such rather than shipped broken, and source-maintenance-only integrations are not distributed and never become a mandatory dependency of a destination.
