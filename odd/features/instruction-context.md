# Instruction context

What an agent holds in context before it acts, and how a specialized owner is reached once its applicability trigger is reached: the always-loaded instruction set, the conditional owners with their stated triggers, the distribution behaviour that keeps a loading change free of destination migration, and the harness asymmetry between editors.

**Status:** achieved

## Requirements

- [x] R1 — every obligation that must bind before any action is present in the always-loaded instruction set — the root runtime spec together with every document it configures — and an adopting destination receives those obligations through the root runtime spec's core region.
- [x] R2 — a specialized procedure whose scope is a minority of operations is not loaded unconditionally, and its applicability trigger states the action before which its owner must be consulted.
- [x] R3 — a conditionally loaded obligation is described as cooperative guidance rather than runtime enforcement, and no claim of enforcement is attached to a path reference.
- [x] R4 — changing which documents are loaded never changes a cleared path or its distribution mode, so no destination owes a reconciliation for it.
- [x] R5 — a conditionally loaded procedure keeps its authority and acceptance boundaries: delivery work reaches the release workflow before any delivery action, and architecture decision records keep their statuses and acceptance gate.
- [x] R6 — the root runtime spec carries runtime obligation only; contributor adoption, destination-binding and maintenance guidance live in the project's documentation owner.
- [x] R7 — destination-owned instructions in the shared rulebook are available before action in both editors, while action-specific owners are reached through explicit portable triggers.
- [x] R8 — the root runtime spec and the shared behavioral rulebook are distinguishable from their titles alone, so a bare filename reference between them is never ambiguous.
