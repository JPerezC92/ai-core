## Specs

- S1 — A pnpm script at the AICore checkout root invokes the synchronization CLI. Exact requirement: "Add the necessary pnpm project configuration." and "Use **pnpm exclusively**, not npm." Acceptance: run `pnpm aicore --help` from the checkout root and observe usage text on stdout with exit status 0.
- S2 — One simple command synchronizes, choosing enrollment or update automatically. Exact requirement: "Support `sync` as the simple user-facing command." Acceptance: run `sync` against an unbound fixture destination and observe enrollment followed by a currency report; run it again and observe an update without a second enrollment.
- S3 — The destination and editor chosen on a first run are persisted and reused. Exact requirement: "Persist the last explicitly selected destination and editor for future invocations." Acceptance: run with `--target` and `--editor` once, then run `sync` with no arguments and observe it acting on the same destination with the same editor.
- S4 — Explicit arguments override the persisted selection. Exact requirement: "Explicit `--target` and `--editor` arguments override the saved defaults." Acceptance: run once saving destination A, then run with `--target` B and observe the operation act on B and the persisted selection record B.
- S5 — An unimplemented editor is refused, never silently substituted. Exact requirement: "If the requested editor is not yet supported by the existing synchronization behavior, reject that operation clearly rather than silently applying OpenCode files." Acceptance: run `sync --editor cursor` and observe a non-zero exit with a message naming Cursor as unimplemented, and no destination file written.
- S6 — An unknown editor for an existing destination is never inferred. Exact requirement: "Do not silently select an editor for an existing destination whose editor configuration is unknown." Acceptance: run `sync` against a bound destination whose persisted editor is absent and observe a non-zero exit requesting `--editor`, with no write.
- S7 — The source revision is configuration-supplied and Git is never executed by the tool. Exact requirement: "The synchronization engine must not execute Git commands directly." and "Do not weaken source-revision validation." Acceptance: run `sync` with no revision available and observe a non-zero exit naming the revision limitation; run it with a malformed revision and observe rejection by the existing validator.
- S8 — Operator-local configuration is excluded from version control. Exact requirement: "Keep operator-local configuration out of Git." Acceptance: read the repository ignore rules and verify the configuration path is ignored.
- S9 — Source checkout and bindings paths resolve automatically. Exact requirement: "Resolve the source path and bindings path automatically." Acceptance: run `sync` with only a target supplied and observe it locating both without further arguments.
- S10 — Existing advanced commands remain available. Exact requirement: "Keep existing advanced commands available for existing workflows." Acceptance: invoke each existing subcommand through the wrapper and observe the engine's unmodified arguments and exit status.
- S11 — Every existing safety guarantee is preserved. Exact requirement: "Existing sync safety behavior remains unchanged." and "Continue using the existing engine's synchronization and safety mechanisms." Acceptance: run the existing whole suite and observe it passing with the engine untouched.
- S12 — Failures are clear and non-silent, and no failure path writes to a destination. Exact requirement: "Provide clear errors for unavailable configuration, revision, or invalid destination." Acceptance: run `sync` with an invalid destination and observe a non-zero exit naming the problem and no created path.
- S13 — No file relocation, no clearance change, no Cursor claim, no rewrite. Exact requirement: "No files are relocated." "No clearance rules are changed." "No Cursor agent support is falsely advertised." "No Python-to-TypeScript rewrite occurs." Acceptance: diff the candidate against base and observe no relocated tree, no clearance edit, no Cursor parity claim, and the Python engine still present and authoritative.
- S14 — Enrolled production destinations are untouched. Exact requirement: "Enrolled production destinations remain untouched." and "Do not modify either destination as part of U1." Acceptance: compare both enrolled destinations before and after the change and observe no modification.
