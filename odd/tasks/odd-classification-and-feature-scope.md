## Specs

- S1 — Classify work as small only when it is understood, risk-contained, and resumable from the request plus diff; counts of files, commands, tests, fixes, tasks, or requested todo lists never determine size.
- S2 — Read-only work and small work create no durable feature artifact. Other authorized state-changing work uses one ODD feature document created before its first write; authorization and safety gates remain independent.
- S3 — `plan-enforce` does not classify or govern new work. It remains available for legacy-plan migration/resumption, scope changes or new phases within an identified active legacy plan, and user-confirmed legacy PR-merge cleanup; existing plan/story files remain preserved migration records.
- S4 — One feature document bounds one feature's requirements and tasks, not an exclusive set of files. A feature may change a shared rule when the canonical owner, authority, affected resource, and dependency are explicit; it must preserve original obligations and use the existing audit gate.
- S5 — Features that touch the same canonical resource are coordinated as one-writer-at-a-time work. Declare dependencies and serialize conflicting edits; after a base/head change, invalidate affected evidence and review verdicts.
- S6 — No second tracker, Engram mirror, context injection, dependency, permission, plugin, or destination change is introduced.
- S7 — Versioned runtime/spec/skill surfaces advance only by their applicable SemVer rule; documentation and runtime changes preserve all unrelated authority and legacy lifecycle obligations.
- S8 — The change is limited to `AGENTS.md`, `knowledge/agent-workflow.md`, `knowledge/diagnostic-system-design.md`, `knowledge/debt.md`, `README.md`, the `odd-workflow`, `plan-enforce`, and `user-story` skills plus the ODD checklist and the user-story consistency checklist, and the source-version contract fixture. Historical plans/stories remain untouched migration records; no unrelated migration is included.
