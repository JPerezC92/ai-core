## Specs

- S1 — A region-mode sync writes the source's frontmatter identity keys into the destination file. Exact requirement: "Make sync rewrite destination frontmatter". Acceptance: take a destination whose `SKILL.md` carries an older `description`, run `apply` with a newer source revision, then read the destination file; its `description` equals the source's while `<!-- core:begin -->` and everything below it are unchanged.
- S2 — Destination-only frontmatter keys survive the refresh, and `local-version` is never reset. Exact requirement: `AGENTS.md` → Reuse guide → "An AICore sync never resets local-version". Acceptance: refresh a destination agent file that carries `local-version: 1.0.1` and a lower `version`; the destination keeps `local-version: 1.0.1` byte-identically and its `version` becomes the source's.
- S3 — `check` reports drift when a destination's frontmatter identity keys do not match what a sync would write. Exact requirement: derived from S1 — a write that `check` does not verify would report `current` on a file `apply` is about to change. Acceptance: run `check` against a destination holding a stale `description`; it exits non-zero and names the affected path; after `apply`, the same `check` prints `current`.
- S4 — DEBT-038 is retired by explicit user cancellation, not by satisfying its resolution criteria. Exact requirement: `knowledge/debt.md` → "An explicit user decision may cancel an open debt without satisfying its resolution criteria." Acceptance: read `knowledge/debt.md` and confirm it contains no `DEBT-038` heading, then read this record's Log and confirm it preserves the user decision, the unmet criterion and the supporting evidence.
- S5 — No destination project is written by this feature's work. Exact requirement: "dont touch nothing on tismart-support project". Acceptance: inspect the shipped commit `ea88893`; every path lies inside the ai-core repository.

- L8 — 2026-11-05 — Implementation, and one rejected design. The first candidate parsed the frontmatter, merged the mappings and re-serialised with a YAML dump. Rejected before any gate: re-serialising keys the source does not define can rewrite a destination scalar such as `version: 1.10` into `1.1`, silently changing a version string on an adopted project. The accepted implementation is surgical: source-defined blocks are replaced using the source frontmatter's own raw lines, destination-only keys emit their original input slice byte-for-byte, `metadata` merges child by child, and the parser supplies only key sets, ordering and comparison — no value round-trips through it into output. `protected_bytes` replaced `outside_bytes` as the render guard because frontmatter is now a legitimate delta; write-target preflight is unchanged.
