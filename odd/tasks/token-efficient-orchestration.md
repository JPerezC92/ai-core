## Specs

- S1 — "i think the current instructions loaded are fine they have guidelines that are always used, u can review it" Acceptance: review the loaded instruction roles; retain their loading configuration and required safeguards, with no model/provider changes.
- S2 — "Limit delegation for simple tasks. Subagents make additional model calls; your current rules require delegation even for small requests." Acceptance: permit direct bounded coordinator-owned inspection/explanation when no specialist ownership or independent gate applies; preserve incident investigation, code authorship, Git ownership and required reviews. Accept cited direct tool/repository evidence on this route rather than forcing an agent merely for attribution.
- S3 — "Keep searches and reads narrow. Request relevant sections instead of whole files or broad directory scans." Acceptance: named-path-first exploration; expand for an identified dependency or gap. Reuse current complete loaded evidence for ordinary reads, but preserve explicit full-read and fresh-read requirements and invalidate stale evidence.
- S4 — "Use shorter answers and avoid repeated research when current evidence already answers the question." Acceptance: allow compact combined reporting for contiguous preparatory/read-only steps while retaining required states, evidence, blockers and next action; never cross an approval/checkpoint gate. Reuse valid research through its existing owner procedure; investigate missing or stale evidence only. No guaranteed credit or token saving is claimed without measurements.
- S5 — "there are many audits i just noticed warden making a biggest research about dependencies of packages auditing security breaches, i dont want my task to make an entirely audit on external repositories there should be security but not that overscope maybe a pnpm audit ot use semgrep/astgrep" Acceptance: the default dependency gate is bounded and local — the approved audit command plus pin/hash coverage, license and locked-environment checks. Deep publisher-provenance source-correspondence research (registry download, canonical source tag, content diff) applies only to an added or version-changed dependency or an explicit user/session request, never to the whole audited tree and never as a routine step. Preserve BLOCK with no override, hash-mismatch BLOCK, ADVISORY acknowledgment, and upstream review before install. Source-pattern rules (semgrep/astgrep) may add targeted source checks but are never reported as advisory/CVE coverage.
- S6 — "the same for the other subagents i want stability but i feels they are overscoping" Acceptance: audit depth and cadence are proportional to the authorized change. Remove or narrow the unconditional per-session/per-task dependency baseline so unrelated tasks do not trigger a dependency audit; scans become change-triggered or explicitly requested. A role reports out-of-scope areas as not inspected rather than expanding scope. Mandatory full reads of affected files, edit gates, and independent reviews remain intact.
- S7 — "i want stability" Acceptance: no safeguard named in S2–S6 is removed without an explicit obligation-accounting entry naming what it protected and why the replacement is sufficient; every retired obligation appears in the Log accounting before acceptance.
- S8 — "i feels its not self sufficient how u stop a agent to expand widerly a audit?" Acceptance: audit expansion is stopped by an executable boundary, not prose alone. Warden 🔒 (Dependency Warden) receives an agent-scoped closed shell allowlist (deny-all first, then the explicit audit commands) so an out-of-envelope command fails rather than running; each audit dispatch declares its exact package set, allowed commands and zero default external fetches; an out-of-envelope need returns `BLOCKED` with the exact command instead of self-expanding; the coordinator cross-checks the report's executed-command list against the envelope. A widened envelope requires explicit authorization.
- S9 — "i told u about warden as example, u analyzed the others agents?" Acceptance: apply the same proportional-depth principle to every role, not Warden 🔒 (Dependency Warden) alone. No role re-reads a large unchanged document chain per session or per edit when the same content is already current in the run; no two roles re-read the same chain for the same single-axis gate; duplicated rule surfaces and duplicated gates over one unchanged surface collapse to one; a role reports out-of-scope areas as not inspected instead of expanding. Every load-bearing safeguard listed in the Log analysis is explicitly retained.
- S10 — change-triggered cadence: no role runs an unconditional per-session, per-invocation or calendar-driven audit sweep. Background work runs only on a dependency change, a changed target, an explicit request, or a scheduled task the user authorized. Unchanged content may be reused while its identity is recorded; relevant change invalidates the affected verdict.
