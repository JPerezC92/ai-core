# TypeScript Vitest migration

> **Status:** active
> **Owner:** Cipher 🔓 (Lead Orchestrator)
> **Created:** 2026-11-12
> **Objective:** Migrate the TypeScript test suites of the `cli/aicore` package from `node:test` and `node:assert/strict` to Vitest, under the framework decision recorded in ADR 0009, without changing production synchronization behavior or reducing coverage.
> **Branch:** `feat/sync/vitest-migration` — to be created by Herald 📯 (Release Manager) from `feat/sync/pnpm-cli` once the U1 closure commit lands; branch creation and all Git execution belong to Herald.
> **Delivery:** One branch, work units split by concern: (1) the architecture-decision reconciliation and the record bootstrap, (2) the package-local dependency, Vitest configuration and scripts, (3) the unit and integration suite migration, (4) the end-to-end suite migration, (5) verification, gates and closure. The authored forecast is roughly 2,100 changed lines (rewriting 15 test modules), excluding `pnpm-lock.yaml`, `node_modules/` and generated output, so the roughly-400-line strategy trigger applies from the first commit and the slice boundaries are the work units above.
> **Runner:** `pnpm --dir cli/aicore test` (unit and integration, through Vitest), `pnpm --dir cli/aicore test:e2e` (end to end, through Vitest), `pnpm typecheck`, and `uv run --frozen --group dev pytest -q --ignore=.agents` for the unchanged Python synchronization engine.

Load and read the `odd-workflow` skill (`.opencode/skills/odd-workflow/SKILL.md`) before creating or maintaining this record. Its creation, delivery, change and closure procedures are canonical; this template illustrates their layout, not another policy definition.
