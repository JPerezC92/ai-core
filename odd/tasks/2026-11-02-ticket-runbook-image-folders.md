## Specs

- S1 — User request verbatim: "ok i need to improve it in the part when the ticket is readed sometimes the agents download content like images, i want to separate the images that are used for the response and the images downloaded , they need diferent folders additionally remenber the final document can have many responses and each carry their images we need to organize the images used in the responses to not make confusion". Acceptance: downloaded images and response-used images live in different folders; a ticket with many responses keeps each response's used images organized so they cannot be confused with another response's images.
- S2 — User decision verbatim: "wait, it forbids the download from incident images, mmm it seems it continue doing that, whatever can u add a specific folder for those content". Acceptance: add a dedicated inbound folder `downloads/` for downloaded incident-image content. That folder is not the response-image tree. Ledger's current rule that originals are never downloaded or duplicated into `screenshots/` is retained: inbound copies may exist only under `downloads/`; a response `path:` never points at `downloads/`.
- S3 — User decision verbatim: "screenshots/response-N/". Acceptance: images cited in `### Response N` live at `screenshots/response-N/NN_source_entity.png` (existing `NN_<source>_<entity>[_<distinguisher>].png` filename). `ImagenN` numbers inside that response. Quill 🪶 (Note Drafter) audits the current response folder, not every image on disk. A cited local `path:` is ticket-folder-relative `screenshots/response-N/<filename>` and resolves to an existing file.
- S4 — User decision verbatim: "Delete unused at close". Acceptance: at close-out, unused files in `downloads/` are deleted. Only images cited by a posted response survive as local files, under `screenshots/response-N/`. Close still deletes only the analysis working set and `response-draft.md` plus those unused download files; `ticket_<id>.md`, `screenshots/`, `validations/`, and cited evidence are not deleted to satisfy a validator.
