## Specs

- S1 — A fully Core-owned source that no longer exists retires its managed destination file and its binding. Exact requirement: "Delete the corresponding managed destination file. Remove its binding from `.aicore/core.yaml`. Do not preserve obsolete destination modifications. Do not leave orphaned managed files." Acceptance: a raw-bound source deleted from the source tree, synchronized, leaves no destination file and no binding for it.
- S2 — A changed fully Core-owned source updates its destination. Exact requirement: "Update its destination copy to match the current source. AICore remains authoritative for the entire file." Acceptance: a raw-bound destination whose bytes differ is byte-identical to the source after synchronization.
- S3 — A newly cleared source is distributed and bound by the normal synchronization. Exact requirement: "Automatically enroll and distribute them through the normal synchronization workflow. Persist their bindings. Do not require manual reinitialization merely because the source added files." Acceptance: `apply` on an enrolled destination writes a newly cleared source and persists a binding for it.
- S4 — A missing region-managed source keeps its destination file and produces an actionable blocker. Exact requirement: "Preserve the destination file and its content. Record the unresolved condition using the existing reconciliation/blocker mechanism. Produce a clear blocking message identifying the affected source and destination paths." Acceptance: a region-bound source deleted from the source tree keeps a destination file with its project region intact, and the destination blocker names both paths.
- S5 — An unresolved source prevents a full reconciliation claim without stopping unrelated updates. Exact requirement: "An unresolved shared-region file must not prevent unrelated safe synchronization operations from completing. The apply operation may succeed while verification reports that the destination is not fully reconciled." Acceptance: `apply` completes and reports its write result while `check` reports the destination as not current.
- S6 — An existing region-managed source updates only the core region. Exact requirement: "Update only the Core-owned region. Preserve the destination-owned region exactly." Acceptance: after synchronization the destination's project-region text is unchanged and its core region equals the source core.
- S7 — An existing but uncleared source keeps its protection. Exact requirement: "A source file that still exists but is no longer cleared must not be treated as a deleted file." Acceptance: synchronization refuses with the existing uncleared-source drift and writes nothing.
- S8 — Destination-owned files are untouched. Exact requirement: "Files that are not managed by Core Sync must remain untouched." Acceptance: an unbound file inside a managed directory survives synchronization unchanged.
- S9 — A source withdrawn from distribution is retired only when its ownership is established. Exact requirement: "Sources whose previous ownership cannot be established are preserved. Retire fully Core-owned destination files only when ownership and retirement eligibility are established through reliable existing contracts." Acceptance: a withdrawn source whose path the registry still declares retires its destination; one with no covering record is preserved, listed as pending, and named in the blocker.
- S10 — A source whose ownership is not exclusively Core-owned is preserved when it disappears or is withdrawn. Exact requirement: "Only exclusively Core-owned managed files may be automatically removed. Shared region-managed and merge-managed files must be preserved for reconciliation." Acceptance: a merge-managed source deleted from the source tree keeps its destination JSON file byte-for-byte and its binding, and is reported as requiring reconciliation.
