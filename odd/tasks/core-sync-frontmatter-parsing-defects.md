- S2 — F1 (HIGH). `render_init_file` must not concatenate the destination frontmatter directly with `<!-- core:begin -->`. Acceptance: `render_init_file('---\nname: x\n---', 'CORE')` yields a result whose `split_regions` returns a marker pair, not `None`, and whose begin marker is an exact line; output for a destination already ending in a newline is byte-identical to today's.
- S3 — F2 (MEDIUM). A frontmatter delimiter is an exact `---` line with no leading or trailing whitespace. Acceptance: `split_frontmatter("  ---  \nrule\n  ---  \nbody\n")` returns `("", "  ---  \nrule\n  ---  \nbody\n")`, and `extract_source_core` of that content returns it unchanged rather than dropping `rule`.
- S4 — F3 (MEDIUM). The frontmatter closing-delimiter scan must ignore `---` lines inside fenced code blocks, using the same fence rule as `markers._exact_marker_line_indices`. Acceptance: frontmatter whose body contains a fenced `---` returns the complete frontmatter through the true closing bookend; no keys and no bookend leak into the body.
- S5 — SUPERSEDED by S9 (user corrections L6, L7). - S6 — F5 (LOW). Publish `path_is_within` as a public domain helper and import that name from `infrastructure/filesystem.py`; behavior is unchanged. Acceptance: `grep` shows no `_path_is_within` import across modules; existing containment tests still pass.

Acceptance: the new tests fail against the pre-fix code (RED observed) and pass after (GREEN).
- S9 — User requirement, verbatim: "all our files sync should terminate in LF". Every text file core-sync writes carries LF line terminators only: no `\r` byte survives in a written output. Acceptance: syncing a CRLF destination in region mode produces a destination file with no `\r`; a CRLF source core region is written as LF; merge-mode text output is LF; `.aicore/core.yaml` and reconciliation reports are LF. Scope boundary recorded with evidence: `raw` mode stays byte-exact because its shipped contract is byte-for-byte copying, and binary payloads are never line-ending-transformed — S9 changes region-mode and merge-mode text output only, and any contrary reading returns to the user before mutation.
