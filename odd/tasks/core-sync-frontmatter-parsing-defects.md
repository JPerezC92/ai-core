- S9 — User requirement, verbatim: "all our files sync should terminate in LF". Every text file core-sync writes carries LF line terminators only: no `\r` byte survives in a written output. Acceptance: syncing a CRLF destination in region mode produces a destination file with no `\r`; a CRLF source core region is written as LF; merge-mode text output is LF. Scope boundary recorded with evidence and confirmed by the user decision in L18: `raw` mode stays byte-exact because its shipped contract is byte-for-byte copying; binary payloads are never line-ending-transformed; and a destination artifact that is already semantically in sync is **not** rewritten merely to normalize its endings — destination files we do not need to change are destination-owned. S9 therefore constrains what core-sync writes, never what it leaves untouched.
