## Specs

- S1 — User requirement, verbatim: "i am being clear i just want taht the scanner runs just before the last UPLOAD of THE PR U UNDERSTAND? AND RUNS OVER THE LOCAL PR FILE THAT IS UPLOADED". Acceptance: the scan runs over the exact local working-body bytes that the single final `gh pr edit --body-file` upload publishes, immediately before that upload. No other scanning behaviour changes, is added, or is removed.
- S2 — User requirement, verbatim: "there are already tools created dont duplicate them if they can be adapted is better". Acceptance: extend the existing `.opencode/skills/git-pr/scripts/prepare_pr_review.py` CLI and reuse the existing `prepare_local_snapshot`, `assemble_snapshot`, `validate_local_inventory`, `ReviewPreparationError` and `create_text`, plus the existing scanner. No new skill, no second CLI, no replacement matcher; `verified-pr-cleanup` is neither imported nor modified.
- S3 — Requirement context, verbatim: "is supposed our current way is to build the PR locally and when it is ready is uploaded to githud and overwrite anything contentn on the PR with the last correactions madded locally, now the attribution scanner should run with the final local file before it is uploaded". Acceptance: the scan input is built from the local draft and local working body plus read-only Git data. The new command performs no GitHub call, and no persisted body is fetched by it.
- S4 — Fail closed and do not disturb existing behaviour. Acceptance: an unresolved base ref or HEAD, an empty commit range, an empty changed-path list, a path-set mismatch or any Git failure exits non-zero and creates no output file; deleted paths are retained; every existing subcommand keeps byte-identical behaviour; outputs stay exclusive-create.
- S5 — User requirement, verbatim: "what about the instructions of realease and the agent they will know how is the new flow?" Acceptance: the new step is stated where the acting agents actually read it — `.opencode/agents/inquisitor.md` step 7 names the pre-upload scan as required immediately before the single upload, `.opencode/skills/git-pr/references/_pr-evidence-format.md` requires the same scan over the exact uploaded bytes and stops calling a pre-write scan simply insufficient, and `.opencode/skills/git-pr/SKILL.md` documents the command. Without these the command is inert. Stay unchanged: the persisted-body scan, `verify`, every other posting control, `herald.md` and `knowledge/release.md`.
