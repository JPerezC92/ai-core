## The seven conflicts, each with its guardrail (brief Q6)

1. **"No approval gate before implementation" vs the execution-authorization turn — CONFLICT.** `infer:` (05 §1) ODD authorizes from the request itself (step 1, S4) and only delivery actions "require their own explicit authorization" (S14, S5). The plan preserves "the later execution-authorization turn" and user-only gates (plan, Context and authority; Verification, Completion). Adopting ODD's authorization model would remove a gate the plan explicitly preserves. **Guardrail:** the execution-authorization turn and user-only gates are non-negotiable; no adoption may route around them. This is a real boundary conflict, not a wording difference.
2. **Automatic task tracking vs the preserved plan-enforce binding — CONFLICT.** ODD runs "without you asking for a workflow, a plan, or task tracking" (S4) and its tracking writes `odd/tasks/` plus an Engram mirror before the first source write (S4). The plan requires "Keep the existing plan-enforce binding and its default applicability unchanged" (plan, Context and authority) and forbids "an extra workflow index, engineering handbook, skill, or competing story catalogue" (plan, Target structure placement rules). A second automatic tracker is a competing plan/task system — out of bounds by the plan's own text. **Guardrail:** plan-enforce remains the single binding; never run a second automatic tracker beside it.
3. **"Small, understood work creates no durable task artifacts" (S4, S5) vs plan-required-for-non-trivial-work — CONFLICT of thresholds.** ODD's resumability test would classify many planned instruction/document edits as "small" and skip durable artifacts entirely (S4). The repo's default requires a plan for non-trivial work, and the current one-task exception "is not a permanent bypass" (plan, Context and authority). `infer:` the conflict is about who sets the threshold — per-request harness inference vs a binding default — and cannot be settled by importing ODD's rule. **Guardrail:** threshold authority stays with the plan's binding default; ODD's resumability test may inform eligibility wording (see [`04-recommendations.md`](04-recommendations.md), proposal 1) but never override the default.
4. **Adopting the tools (gentle-ai, engram) vs exclusions and Warden 🔒 (Dependency Warden) — CONFLICT.** The plan excludes "runner/model/dependency changes" and "adopter mutations" (plan, Still excluded), requires Warden 🔒 (Dependency Warden) review even for a narrow config delta (plan, Execution contracts 2), and records "No destination sync or destination mutation is authorized" (plan, First increment note). gentle-ai is an "ecosystem configurator" that writes system prompts, skills, routing and MCP entries into each agent's config with `state.json`-tracked writes (research set, 01 §5; S9); engram is a new MCP/SQLite dependency (S17). Both are dependency and harness-config changes by the plan's own definitions. `infer:` adopting them in this program is inadmissible without a separate, explicitly authorized dependency decision. **Guardrail:** tool adoption is a separate dependency decision under Warden 🔒 (Dependency Warden) review only (see [`04-recommendations.md`](04-recommendations.md), proposal 8).
5. **RDD default-on / duplicate review authority / causal rule overreach — CONFLICT, multi-part.** (a) RDD is on by default, opt-out since v3.5.0, and publicly contested (issue #3412, S15; S11) — a default this repo would inherit silently; the repo's review gates are deliberately dispatched and named (plan, Execution contracts 1 and 4; Execution and ownership 5). (b) Even ODD treats review as separable — "ODD never enables RDD" (S4) — so an adopted RDD lifecycle would run parallel to Sentinel 🛡️ (Quality Guardian) and Inquisitor 🔎 (PR Reviewer), creating duplicate review authority the plan does not budget for. (c) RDD's authority burn (`acknowledge-approved`, S6) is a tool-owned lifecycle; the plan's verdicts are coordinator-accepted `[PASS]`/`[PENDING]` records (plan, Foundation planning review; Current preparation state). (d) The causal-admission rule (S8) applied literally would wrongly defer authority/safety stops the change did not cause (plan, For encountered defects). **Guardrails:** never inherit RDD's default-on silently; no parallel review authority beside Sentinel 🛡️ (Quality Guardian) / Inquisitor 🔎 (PR Reviewer); tool-owned lifecycle states never replace coordinator-accepted verdicts; and — most important — **causal admission must be explicitly subordinated to the plan's safety/authority stop conditions** ("unmet selected requirements, safety/authority conflicts, or necessary scope changes", plan, For encountered defects): a finding may be *routed* by causality, but a safety/authority conflict stops affected work whether or not this change caused it (`infer:`).
6. **Single-repo harness writes vs core-sync / destination-mutation boundaries — CONFLICT.** gentle-ai writes into each agent's own configuration surfaces (research set, 01 §5; S9), and its persona mode persists a persona file (`~/.pi/gentle-ai/persona.json`, S20). The plan requires shared text be neutral with "No destination is contacted or modified" (plan, Portable-set review) and keeps "persona only; no workflow duplication" at `agents/<name>/profile.md` (plan, Target structure). `infer:` an external configurator writing runtime surfaces violates both the source/destination split and the plan's own-file-ownership model; the Engram mirror's non-atomic writes ("Read back both writes", S4) would additionally create a second task-state authority beside the plan's "filesystem-as-evidence" discipline (plan, Revalidation RV-01). **Guardrail:** no external configurator writes runtime surfaces; the source/destination split, per-file ownership, and filesystem-as-evidence hold.
7. **ODD's one-file living document vs transcript prohibition — CONFLICT (structural).** `## Log` accumulates "corrections, evidence, and rationale" for the life of the feature (S4); the plan forbids "append[ing] running execution transcripts" (plan, Small-document budgets), keeps `plans/<task>/plan.md` explicitly temporary ("not durable requirements", plan, Target structure), and demands history live at durable owners (plan, Execution contracts 6; R3). `infer:` importing the feature-document shape would reintroduce exactly the bloat the plan is repairing. **Guardrail:** never import the one-file living-document shape; history lives at durable owners, plans stay temporary.

## Non-fits (not conflicts)

- **TDD.** ODD's test-first is conditional: it applies "when a relevant runnable deterministic test and a clear expected outcome exist" and "never invent a runner" (S4). `infer:` this is compatible with the plan's exclusion of "artificial TDD for document edits" (plan, Still excluded) and would *not* resurface the withdrawn TDD-pilot finding — but importing an unconditional TDD mandate would (plan, Foundation planning review: the withdrawn finding was rejected as "unsupported scope expansion").
- **`gentle-ai doctor` health checks (S4)** — no plan surface in stages A–G.
- **Delivery strategies (`ask-on-risk` etc., S4)** — no plan surface in stages A–G.
- **The four 4R lenses (S8)** — no plan surface in stages A–G.

## Real boundary conflicts vs wording differences (plain statement)

- **All seven conflicts above are real boundary conflicts**, not wording differences — each is a conflict over who holds authority or where a boundary lies: 1 (implementation authority), 2 (system-of-record authority), 3 (threshold authority), 4 (scope/dependency boundary), 5 (review authority plus causal overreach into safety/authority stops), 6 (destination/ownership boundary), 7 (document-structure boundary). Conflict 1 is flagged in the source as "a real boundary conflict, not a wording difference"; the same classification extends to 2–7 on their stated grounds (`infer:`).
- **The genuinely non-boundary divergences are wording-, method- or policy-level and must not be laundered into conflict — nor smoothed away:** the correction-round mismatch (RDD one round vs the plan's two, S6 / plan, Verification, Stop) is a policy question ([`README.md`](README.md) gap 4); the 400-line heuristic vs Small-document budgets is a different-objects mismatch, explicitly downgraded (gap 3); question routing differs on *who* may ask (role-agnostic vs user-only via Cipher 🔓 (Lead Orchestrator)) while agreeing on *when* to ask; and "honest report" vs the close triad is pure terminology (gap 8).
