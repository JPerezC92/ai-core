# Source-local architecture records

This document holds this repository's source-local architecture selections, decision records, and history; it is not distributed, because `.aicore/core/architecture/` ships whole-file and every file in it refers only to paths inside that root. Read it as explanation and navigation for work in this repository — never as a shared dependency and never as a second architecture authority.

## Current source selections

The previously approved import interpretations are mapped by `.aicore/core/architecture/implementation/stacks/typescript/react.md` and `.aicore/core/architecture/implementation/stacks/typescript/nestjs.md` → Imports and language conventions, and `.aicore/core/architecture/implementation/stacks/python.md` → Imports and language conventions → Deployment zones. Its framework-free entity choice does not select a framework for unrelated DTO/configuration roles or establish application conformance.

The Python guide supplies native Python filenames; the NestJS guide's Concept-role filenames table supplies TS/JS syntax, reused by the React guide without selecting NestJS dependencies or a reviewed JavaScript framework stack. Independent owner and documentary semantic acceptance are recorded in [ADR 0007](decisions/0007-domain-model-repositories-and-naming.md) and the [research record](../research/architecture/domain-model-repositories-and-naming/README.md); the governing feature record that first logged them was retired under the seven-day retention policy. These pointers do not certify implementation adoption.

No Python HTTP framework, repository library, error registry layout or serializer framework mapping has been selected. These project selections remain open; current implementation patterns do not decide them. Follow `.aicore/core/architecture/implementation/stacks/python.md` → Open decisions. A missing mapping for an uncovered concern is not a blocker and never requires an uncertainty verdict: implement and review that concern against `.aicore/core/architecture/implementation/architecture.md` and the applicable shapes, with execution choices kept to evidenced project-owned bindings. A real contradiction, missing authority, or decision-critical evidence gap still halts the affected operation through the applicable runtime's uncertainty route. Unselected bindings alone are not blockers for unrelated work.

## Decision rationale

AICore's architectural decision records live in [`decisions/`](decisions/) — the source-local ADR directory, not a shared path. [Architecture Decision Workflow](../../.aicore/core/knowledge/architecture-decision-workflow.md) owns the decision lifecycle and the requirement that an accepted decision propagates into its architecture owner. The records are [ADR 0001 — Agent workflow foundation](decisions/0001-agent-workflow-foundation.md), [ADR 0002 — Testing architecture layering](decisions/0002-testing-architecture-layering.md), [ADR 0003 — Architecture documentation ownership](decisions/0003-architecture-documentation.md), [ADR 0004 — Domain behavior placement](decisions/0004-domain-behavior-placement.md), [ADR 0005 — Use-case organization and naming](decisions/0005-use-case-organization-and-naming.md), [ADR 0007 — Domain model, repositories and naming](decisions/0007-domain-model-repositories-and-naming.md), [ADR 0008 — Package-local tests for independently deployable applications](decisions/0008-package-local-tests.md) and [ADR 0009 — TypeScript test framework convention](decisions/0009-typescript-test-framework.md). ADR 0001 covers the agent-workflow budget; ADR 0002 and ADR 0003 own the testing and architecture-document layout, and ADR 0004, ADR 0005 and ADR 0007 own the domain and operation rules above. Two clauses of these records were superseded on 2026-11-12: ADR 0002's colocation requirement and ADR 0005's per-stack operation-shape freedom; their status lines carry the superseding decision, and the operative rules are `.aicore/core/architecture/testing/architecture.md` → `T10` and `.aicore/core/architecture/implementation/architecture.md` → `C3 — Application operation`. Shared core never links source-local ADRs: the owners state their own rules, and an ADR is explanation, not an undistributed dependency. **Path note:** these records name the shared paths as they stood when each decision was accepted, and those trees now live under `.aicore/core/` — `architecture/` → `.aicore/core/architecture/`, `knowledge/` → `.aicore/core/knowledge/`, `odd/` → `.aicore/core/odd/`. A path relocation changes no decision's rule, so the records are not rewritten and this single note is their mapping; read any path they name inside that tree.

ADR 0006 — Architecture whole-file distribution and contract boundaries — was removed on 2026-11-01 by explicit user decision because it was never used; its decision content is folded into ADR 0003's 2026-11-01 amendment.

[ADR 0009 — TypeScript test framework convention](decisions/0009-typescript-test-framework.md) is **Proposed** on 2026-11-12 and carries no obligation while it stays proposed: it records Vitest as AICore's TypeScript testing framework and the boundary that the migration is a separately authorized change. It propagates no normative change — `.aicore/core/architecture/testing/stacks/typescript.md` already names Vitest as the single runner and keeps runner and framework bindings project-owned, so the binding lives in AICore's own package configuration. The operative testing rules remain those of `.aicore/core/architecture/testing/architecture.md` and the applicable stack guide.

[ADR 0007 — Domain models, repositories and naming](decisions/0007-domain-model-repositories-and-naming.md) is **Accepted** on 2026-11-05 following verified owner propagation and explicit user acceptance (feature L25/L28/L30). The architecture owners, not the ADR, carry operative authority. Its [research record](../research/architecture/domain-model-repositories-and-naming/README.md) preserves bounded evidence and distinguishes user-selected conventions from source findings. ADR 0004's documentary annotation preserves its accepted body and points to the current definitions without declaring supersession. No implementation conformance or remediation is claimed.
